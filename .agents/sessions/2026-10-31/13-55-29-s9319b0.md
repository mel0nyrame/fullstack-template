### 对外答复

先纠正两个理解，再给现实版计划。

**一、仓库结构：一个仓库，两个文件夹**

不需要另建 "front 仓库" 和 "back 仓库"。你现在这个文件夹就是一个仓库，`frontend/`、`backend/` 是里面的两个目录；以后前端代码放 `frontend/`，后端代码放 `backend/`，交的就是这一个仓库。你的 fork 就是你的作业仓库（`origin` 已指向它）。

**二、PR 是什么，为什么你没看到**

PR = "请把我的分支合进 master" 的申请，在你自己仓库里操作：GitHub 打开仓库 → Pull requests → New pull request → base 选 `master`、compare 选 `feat/web-practice` → 填标题和说明 → Create pull request → Files changed 看差异 → Merge pull request。你现在有分支但没建 PR，所以看不到。首次练习清单就是这些"必须你亲手做一次"的操作；commit、push 已算完成，PR、合并、启动、构建、F12 仍待练习。

20 天 ≈ 3 周 ≈ 18 小时，零基础要同时学 Java、SQL、Spring Boot、Vue、JavaScript。按原版全部完成不现实。考核文档本身允许"学到哪里做到哪里、未完成如实标注"，所以策略是：**做一个能演示、能讲清的最小闭环**，把没做的写清楚。建议今天就给负责人发一条进度说明：零基础、每周 6 小时、计划做到哪一步、哪些暂不实现，问能否按阶段验收。
